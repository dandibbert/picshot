## Status rules

- **Code**: a reachable implementation was found for the narrowly stated row. This does not mean a build, test, or real-device acceptance run passed.
- **Partial**: some implementation exists, but the row's full behavior is incomplete or materially constrained.
- **Missing**: no reachable implementation was found in the stated source snapshot. An unintegrated prototype, menu label, placeholder, API type, or proposed dependency does not count.
- **Platform**: vendor documents the behavior as Windows-specific; a macOS adaptation is separately identified, never quietly counted as implemented.
- **Unverified source**: explicitly requested scope retained, but the consulted primary documents do not yet substantiate that exact variant.
- **Test state is independent of code state.** Code/Partial rows describe reachable implementations at their stated source boundary, not complete acceptance or delivery. Delivered ARM `6a154fb` and app-identical Intel `b0b0eab` pass their 0.6 pipelines and installed formats. Pre-final `9b63ddf` passes both architectures, but does not replace final-source evidence. The 0.7 `8e43f67` batch has its own early ARM UI-only evidence, but test compilation failed and full installed/resource gates remain pending; no pass is transferred to the current local fixes. Separate GIF-attribution measurements retain source `87eaedf`. Residual growth, real-device checks and Missing/Partial behavior remain open. [VERIFICATION.md](VERIFICATION.md) records exact and historical results; fixtures do not establish full parity or leak freedom.

The acceptance column remains the full required check for each row. Some fixture-level checks now have recorded passes, but **no row is closed for complete parity** merely by being marked Code or having a unit test. Closure requires a final implementation reference, exact commit, relevant automated result and the required real-device evidence. Missing and Partial rows remain in scope until completed or the user explicitly changes the goal.

### Current main gaps

The immediate gate is native build/test and installed ZIP/DMG evidence on both architectures for 0.7 presets/AX, encoded preview/BMP/paged PDF and barcode interaction. High-use gaps remain: real cross-application AX/TCC and preset re-invocation on physical displays; multiple-window selection; polyline arrow/join/end controls, matching/synchronized mosaic, text outline and advanced callouts; rendered LaTeX pins, collective transforms and per-desktop visibility; automatic pin OCR, linked separate-result/source overlays, physical external-app text drag and broad multilingual/barcode quality; continuous manual scrolling, adjustable capture regions and live-app/large-preview acceptance; recording click/scroll/keystroke effects, animated WebP, sustained resources and real-device camera/recovery; integrated WebP/AVIF export, naming/templates/quick-save and advanced save controls; table input routes/quality, multi-formula recognition and Office/Typst/AsciiMath interchange; runtime-validated translation, image translation and configuration sync. Named presets, BMP, paged PDF and preview are now authored implementation, not completed runtime acceptance.

Earlier 0.4 additions include frozen screen-anchored region editing and boundary adjustment; all-display composition and delay/cursor preferences; advanced-selection precision HUD and pixel nudging; annotation handles, rotation, inline wrapped text and style inspector; managed persistent image/text/HTML/file/color/animated pins and groups; automatic scrolling; recording pause/restart/countdown, preview and endpoint trim; local MathJax preview and MathML/SVG/PNG/PDF export. The available ARM/Intel 0.5 implementation adds the four annotation effects, opt-in camera/live annotation composition, journaled recording/preview recovery and measured GIF process isolation. Passing fixture/package gates do not close the remaining behavior, quality or real-device requirements.

The editor has **20 modes including Select and Crop in 9b63ddf** (17 in 0.5, 13 in 0.4); toolbar entries are not complete annotation-family counts. Managed text pins remain read-only; selecting recognized text on image pins is a separate new feature. Recording-GIF UI export remains capped at 30 seconds per chosen interval and supports **opaque frames only**; actual transparency is rejected and animated GIF/WebP pin reading is unchanged. Microphone and Apple local translation require macOS 15+. Actual language-download/translation, live screen/audio and multi-monitor paths remain unverified. Earlier native UI uses original 1× synthetic desktops, 1024 × 768 ARM / 1920 × 1080 Intel. The new ARM path fixture uses a separate 1024 × 760 synthetic desktop with native controls/synthetic events. The new pin fixture runs actual local Vision on authored images; neither fixture captures the user's desktop, posts global input or grants TCC.

### Required evidence before a release claim

1. Build and run the final commit's entire test suite on supported arm64 and x86_64 macOS runners. Record exact commit, OS/Xcode and complete logs, including any skipped tests.
2. Install both actual ZIP and DMG artifacts into clean destinations, check expected architecture/signature, launch through normal LaunchServices, and inspect native windows. Record artifact hashes and limitations.
3. Run real-device TCC grant/deny/revoke flows and capture tests with two monitors, mixed pixel scales, non-primary focus, display removal and fullscreen Spaces.
4. Exercise complete user paths: capture → annotate → copy/export → pin → OCR → history reopen. Test repeated invocation, Escape, close/cancel, dialog dismissal and reopening.
5. Independently decode export formats and recording streams. Verify colors/alpha, clip duration, frame timing and audio sync, not just file existence.
6. Measure memory/disk use over sustained capture, long images, repeated open/close and bounded recording; inspect retained resources. Synthetic RSS measurements do not establish leak freedom.
7. Validate each premium-equivalent feature with held-out fixtures, licensing and local/network behavior. Keep disabled/unimplemented functions visibly incomplete.
8. Reconcile every ledger row against the exact release commit. Do not replace missing features with “native alternative” unless the required outcome is actually equivalent and tested.
