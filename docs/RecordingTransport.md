# Compact recording controls

The 0.18 candidate adds a 300×40-point native recording strip with a separate drag grip, Pause/Resume, Stop-and-Save and Expand controls. The selected display's AppKit coordinates determine its initial location; controls clamp to the visible work area, including negative display origins. New takes reset placement beside their target. Same-take expand/collapse, status updates and shortcut-label changes preserve a dragged position. Moving controls never moves the recorded region.

The expanded panel, strip and global shortcuts share one command owner. Stop closes optional input admission synchronously, supersedes a queued Pause, waits for an already accepted Pause/Resume transition, and joins a single durable save and preview. Countdown cancellation, save-before-restart, explicit discard confirmation, prior-take preview and pending-file recovery remain available. A Quit request cancels and drains unfinished region selection, or follows the existing countdown/save/preservation path if capture has already advanced.

The two recording shortcuts are unassigned by default and configurable in Settings. Existing action IDs, saved bindings and cleared actions are preserved. Recording chords register only during a take, including pause; all global shortcuts remain suspended while Settings captures a new combination. Held keys, stale events and queued callbacks cannot cross remapping or take boundaries. Registration failures remain visible through the existing unavailable-shortcut reporting.

Configured transport chords are excluded from optional input-effect rendering before focused-element lookup and before Carbon command dispatch, regardless of callback ordering. No additional global monitor, text capture or OS permission request is introduced. Existing input effects remain opt-in and never inspect ordinary typed characters or accessibility text values. Real physical keyboard layouts, conflicts, TCC, secure/custom controls, display changes and Space behavior require testing on a physical Mac.

Native fixtures use local AppKit button clicks, hit tests, grip drags, light/dark snapshots, unclipped/nonoverlapping bounds and repeated ownership checks. Injected service tests cover command races and cancellation without ScreenCaptureKit permissions. The separate derived-export fixture checks effects after endpoint trimming and every stored GIF/WebP frame; see [its exact contract](recording-input-derived-validation.md).

At authoring time, the candidate contains 1,897 native methods across 213 classes: all original 1,836 IDs plus 61 new IDs. Native discovery, compile, focused/full execution, actual-model gates, installed ZIP/DMG and production-default resource validation remain mandatory. The source-derived count and portable checker tests are not native acceptance. ARM0.17/build159 remains the latest accepted installer until these gates complete.
