# Source-format owned copy candidate (diagnostic only)

This candidate extends the exact build118 source (`eb320ff6bda329f9b76138fd953acc68024f814b`). It does not change production persistence decoders, originals, ImageEditor code, timestamps, default routing, workflow configuration, or export failure behavior. No new format is production-qualified by this patch.

`SourceFormatOwnedCopy.copy` synchronously returns either an explicitly owned CGImage and byte count, or the identical source image with an unsupported-format reason. Invalid bounds, admission refusal, allocation failure, cancellation, a vImage error, mutated buffer/format, or provider/image construction failure throw. An attempted eligible copy never silently falls back. General source-shape validation precedes eligibility, while destination byte/dimension admission applies only to eligible copies; a valid unsupported image can return unchanged even when it exceeds the copy budget.

The candidate tries integer RGB8/RGB16 layouts with three components or four components (straight, premultiplied, or skipped first/last alpha), explicit supported byte orders, and nil decode. It returns unchanged for masks, decode arrays, unsupported color models, float formats, depths, layouts, or byte orders. Format eligibility is experimental until its native byte tests pass on both architectures. RGB color spaces are passed through as the actual source object, including P3, linear, device and ICC instances. Unsupported RGB layouts are not normalized to a different format.

The helper uses a completely populated vImage format matching source depth, bitmapInfo, color-space object and intent. Apple documents that matching properties avoid the any-to-any conversion step. It passes a zero-initialized, checked source-stride buffer with `kvImageNoAllocate`, verifies the pointer/shape/stride and all format fields afterward, and creates the output with the same metadata, interpolation and intent. It does not create a CGContext. Its provider owns only destination storage plus optional scalar lifetime accounting. The allocator can report failure; arithmetic and source-plus-destination admission are checked before allocating. The copy-work byte limit is not a bound on total process memory or framework scratch.

Primary API contracts:
- [vImageBuffer_InitWithCGImage](https://developer.apple.com/documentation/accelerate/vimagebuffer_initwithcgimage(_:_:_:_:_:))
- [vImage_CGImageFormat](https://developer.apple.com/documentation/accelerate/vimage_cgimageformat)
- [vImage decode array transforms](https://developer.apple.com/documentation/accelerate/vimage_cgimageformat/decode)

## Evidence boundaries

The component matrix gains only `png-decode-preserved-draw`, making nine fresh processes. It keeps the immutable build113 generation/pixel hashes, original full PNG inputs, fixed destinations, two warmups/eight measured cycles, and all existing consumer functions. The new cycle does three unchanged full ImageIO decodes, three source-format owned copies, then three existing complete canonical draws. It reports six image creations, three copies, zero fallbacks, zero failures, and source metadata, bytes, decode/copy/release checkpoints plus existing eight task counters, sampled peaks and increments.

Raw source/owned provider comparisons run exclusively in the fresh certification process and native unit fixtures. The new certificate includes every active RGBA sample row, exact metadata, matching raw digests and exact provider-release accounting for all three PNG roles. Measured consumers retain scalar certificate evidence and its hash; they neither obtain nor retain raw provider Data. This prevents an extra full-raster readback from becoming an unreported memory intervention. Canonical draw bytes are additional output evidence, not the hidden-RGB or 16-bit oracle. File descriptors, supplied reference scopes and exact destination callbacks do not prove ImageIO's private native backing was released.

`SourceFormatOwnedCopyTests` covers known straight RGBA8 hidden RGB at alpha zero, low alpha and opaque samples; first/last and premultiplied layouts; RGB and skipped alpha; exact 16-bit low samples and byte orders; padded rows; sRGB/P3/linear/device/ICC objects, intent and interpolation; decode/gray/mask/float fallback; arithmetic and one-byte admission refusal; every cancellation fence; final callbacks; failed second-role cleanup; and actual Data/URL ImageIO decode routes followed by file deletion. It reads raw provider bytes without CGContext rendering. Padding is retained as row storage but is not a meaningful component, and skipped components are excluded from the native significant-sample oracle.

Native compilation, native fixtures, full-size exact-byte certification, and memory results remain pending. Portable source/checker contracts cannot establish those outcomes. The owner must include `SourceFormatOwnedCopyTests` alongside `EditableComponentFixtureTests` in native discovery/selection and increase the matrix outer bound for nine wrappers (nine times 625 seconds, before packaging/check overhead).
