The shared application runner reserves the same active-run owner used by normal region/image chains; it cannot queue another image-bearing request or silently fall back to recapture.

OCR failure can retry the retained frozen image. Successful OCR releases the raster; script failure retries frozen OCR/source, and failed checked Copy retries only the cached transformed text. Runtime/helper limits, sole sandbox entitlement, fixed error codes and sampled 256 MiB RSS threshold remain unchanged. The threshold is still not a hard allocation cap. The long-capture source stays paused, and retry never starts Auto or reacquires the screen.

Cancellation before an acknowledged text receipt returns the preserved long capture in a paused state after the runner and any helper cleanup settle. A later explicit script invocation is a new run over the then-current capture. A committed Copy receipt wins a subsequent cancellation race and retires the live capture once; it cannot become a failed or repeated output. The terminal bridge checks the exact frozen script ID/name, existing-image text route, run ID, Copy output and empty image-output receipts. Duplicate or foreign completions cannot retire another session. Closing the capture cancels its owned runner synchronously, then waits for held OCR/helper settlement before final closure. Terminal/session state retains metadata only; no script body or raster is kept merely to await that value-only event.

Only deliberately saved definitions persist. Generated evidence files contain test text only. User images, recognized text, transformed text and run receipts gain no catalog or diagnostic persistence route.
