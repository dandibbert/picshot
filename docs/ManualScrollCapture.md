## User flow

1. Open **长截图** (long capture), select **纵向 ↕** or **横向 ↔**, and choose the display. Click **选择区域并连续捕获**. Select a region completely inside one target window, excluding fixed headers, sidebars, scrollbars and animation where possible. Screen Recording access is required.
2. A three-second countdown gives you time to return to the target page. The main capture window hides and a compact, nonactivating **手动连续捕获** panel remains. **You scroll the page yourself.** PicShot observes the selected region; manual mode sends no scroll/input events and does not use Accessibility APIs.
3. Scroll a short distance on the selected axis, then let the image settle. Keep at least **25% overlap** and enough distinctive content between accepted viewports. Both directions are supported. “Continuous” means repeated observation without a next-frame click; it does not promise to capture every intermediate frame while content is moving.
4. Use **暂停** to pause. Wait until the current operation drains and **继续** or **重试** becomes available. The main window returns for inspection. A fresh pair of stable observations is required after resuming; an uncommitted pre-pause frame is never adopted. Resume does not repeat the initial countdown.
5. If needed, use **移动选区** while paused. Drag the fixed-size box, press Return to confirm, or Escape to cancel. A successful move leaves the run paused: explicitly click **继续**. The following candidate still has to pass overlap checks.
6. Use **停止**, or close the compact control panel, to stop observation and retain the accepted sequence. You can inspect the preview, edit cuts, finish, or explicitly start **连续捕获** again. To trim, stop first, choose **裁剪片段…**, then apply or cancel the edits before starting another capture run or finishing. Closing the main long-capture window discards its temporary session; it is not a durable save or crash-recovery checkpoint.
7. Choose **完成并编辑** to compose the committed projection and hand it to the existing image editor for the normal copy, save, pin and recognition workflows. Finishing does not use sampled preview pixels. Pending crop edits must first be applied or cancelled. Stop preserves committed frames even if an already-started SDK operation takes longer to drain; cancellation/generation checks prevent its late result from changing the committed handoff.

**Automatic scrolling is a separate action.** **自动滚动（3秒）** starts the existing input-emitting down/right mode after at least one source frame has been accepted. It requires pre-existing Accessibility and screen access. Starting manual observation does not start automatic scrolling, grant permission or validate the automatic mode in a third-party application.

## Stable observations and recoverable seams

The default observer waits for **two consecutive identical observations**, with **0.25 seconds between iterations plus capture/matching work**. Each observation hashes all normalized premultiplied sRGB RGBA pixels with SHA-256 and includes the dimensions. It is full-color equality, not sparse sampling or a luminance-only change detector. Matching is a separate step: the existing conservative bidirectional matcher proposes a signed translation, then the stored sequence overlap is checked before committing.

A stationary viewport is not repeatedly appended. A verified revisit inside captured coverage moves the document viewport without adding another source file. Low texture, ambiguous/missing overlap, mismatched dimensions, full-color conflicts or an obscured/moved target pause with recovery guidance. Return near the last accepted position, reduce the scroll distance, remove the obstruction, and explicitly retry. A rejected candidate leaves the accepted matching anchor, sequence, edits and source bytes intact. This is conservative refusal, not automatic repair of missing content.

After **20 consecutive samples that have not achieved the required stability**, the observer pauses rather than sampling indefinitely. This is not a fixed five-second promise: processing time adds to the interval. A blinking caret, video, loading indicator, color animation or continuing inertial movement can prevent exact equality. The implementation does not mask dynamic regions, remove fixed content automatically, infer semantic page structure, or guarantee broad webpage quality. Persistent instability may require selecting a different region in a new session.

Permission loss, display layout/pixel-scale changes, storage/output limits and capture/matching timeout can end the run with a visible error while preserving accepted content for inspection and completion. They are not all retryable within the same coordinator. Review the failure, then finish or explicitly start a new run where the original target remains valid.

## Paused region moves and immutable originals

- Move is available only in the paused/recoverable state after all pending work drains. It changes position only, within the same display, preserving the region's point/pixel dimensions and scale. Native positions snap to the source pixel grid.
- Target identity remains the same process and window ID. A paused move may follow that window to its new bounds, but it cannot silently adopt another application/window/display. The whole region must fit the visible target. Intersecting foreign overlays are rejected conservatively.
- Escape, close, focus loss, cancellation and display changes during the mover leave the original region intact. A rejected move leaves accepted sources unchanged. Confirming the move does not resume capture.
- Accepted full-resolution PNGs remain immutable in a private temporary spool. Reverse Auto-Crop, trimming, internal cuts and undo/redo change the projection over those files. Preview navigation, movement, retry and rejected candidates do not rewrite them. Reset/main-window close removes the session spool; immutable does not mean retained after close.
- Repositioning provides no guarantee that the next image overlaps. Resizing the viewport, zooming the page, changing display scale or moving to unrelated content does not become supported merely because the box can move.

## Navigable, sampled preview

The stitched projection updates as frames are accepted. During active manual observation the main preview window is hidden; pause or stop to inspect it. The preview offers **适合 / 起点 / 中部 / 终点 / 最新**, zoom buttons, wheel/trackpad panning, magnification and a draggable overview. The teal dashed bands mark the **retained portions of the latest accepted document viewport**, after cuts and reverse Auto-Crop. The overview also outlines the area currently being viewed. A fully cut-away latest viewport has no retained band.

In crop-editing mode a plain drag selects a band; Option-drag pans. Outside editing, a plain drag pans. Home/End and Page Up/Page Down navigate, and Command-wheel zooms. Navigation changes no source pixels or cuts.

The complete overview is capped at **800 pixels on its longest side**. Zoomed detail uses one cached tile, at most **1024 × 1024 / 1,048,576 pixels**, from source thumbnails at most **2048 pixels per side / 4,194,304 pixels**. There is at most one active decoder job and one replacement request; a cancelled job keeps its slot until it returns, and stale results cannot publish. Labels explicitly say sampled. This is not a full-resolution overview or a pixel-perfect substitute for final export. An authored independent small/long edited-fixture pixel oracle is a planned verification gate, not proof already obtained or a promise about every downsampled image.

## Production bounds and memory scope

| Bound | Default production behavior |
| --- | --- |
| Source raster | 24,000,000 pixels, at most 32,768 per side; equal dimensions across the session |
| Output/sequence raster | 60,000,000 pixels, at most 32,768 per side; final RGBA raster at most 240,000,000 bytes before framework overhead |
| Accepted sources | 100 total in the session; stationary samples and verified revisits do not add a source |
| Compressed temporary source files | 512 MiB (536,870,912 bytes); bounded writes refuse excess and remove uncommitted files |
| Manual run | Three minutes wall time, including countdown and pauses; resume does not reset this deadline |
| Observations | 1,200 per explicit manual run; at most one capture or acceptance operation at a time, no queued captures |
| Capture/acceptance timeout | 12 seconds per operation, shortened to the remaining run deadline |
| Cuts/projection | 100 excluded ranges and 300 rendered strips; at least one output pixel band must remain |

Stopping and explicitly starting another manual run creates a new time/sample budget; accepted-source, disk and raster bounds remain attached to the existing session. These are admission/refusal bounds, not tested promises of acceptable latency or stable memory at every maximum.

The coordinator holds digest metadata, while the native driver can hold one uncommitted image and the controller retains the accepted grayscale anchor, overview and spool metadata. Normalization buffers, a preview source sample/tile, decoder state and final composition add working memory. **The native screen path captures the selected full display, then crops the region. A CGImage crop can retain the full-display backing.** The display raster itself must fit the 24 MP/32,768 admission checks. A small selected region therefore does not prove crop-sized native memory use. Injected viewport fixtures do not exercise ScreenCaptureKit or measure this full-display backing path. ImageIO/CoreGraphics may retain volatile decoded backing after lexical release; owned-object cleanup is not process-memory stability.
