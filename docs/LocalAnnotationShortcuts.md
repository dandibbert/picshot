# Local annotation tool shortcuts

The candidate adds an optional local shortcut map for the 20 annotation tools. Build185 had no tool-selection shortcuts; new installations and Restore Defaults therefore leave all tool bindings unassigned. Existing A (selected number comment), Enter, Escape, Delete, arrows, Command-C/S/Z/Shift-Z and boundary controls retain their original behavior.

Settings → 标注快捷键 keeps a value-only draft. Select a tool, record a physical letter/digit key (optionally with Shift), clear a binding, or reset the map. Duplicate assignments and reserved keys show a specific error and preserve the previous draft. Escape cancels key recording. Save Settings commits the map; Cancel and window close discard it. Newly opened editors snapshot the saved map. Already open editors keep their original map.

Labels use fixed US physical-key names, not the active keyboard layout. Physical A is reserved for number comments. The preexisting number-comment command also keeps its character-based precedence: on an alternate layout, an assigned physical key producing “a” still opens the selected number comment. Command, Control, Option, function/navigation and punctuation keys are unavailable to local tool bindings, which keeps them separate from the six global hotkey actions. There is no global/local event monitor, input-monitoring permission, event-character read, accessibility-text query, or keystroke history in this implementation.

Routing occurs only in the owned editor canvas's keyDown when that canvas is the exact first responder in the key window. Text controls, AppKit field editors and marked/IME text do not meet this condition. Sheets, modal windows, native menu tracking, repeats, another event window, active drawing/polyline/crop drafts, inline input, number comments and automatic-mosaic review reject tool switching. A successful shortcut calls the same chooseTool path as a toolbar selection. Region-selection and other capture windows have no shortcut routing.

The persisted value uses annotation.localShortcuts.v1, a JSON object with schemaVersion 1 and a bindings array. Each entry contains exactly tool and binding; a binding contains exactly keyCode and modifiers (0 or 1 for Shift). Missing tools are cleared bindings. The standalone byte decoder caps input at 8 KiB and nesting at 8, bounds entries at 20, and rejects unknown/missing/duplicate fields, duplicate tools/chords, unsupported values and versions. Codable decoding also validates fields, entry counts and values; an enclosing portable JSON document must perform its own duplicate-key preflight before nested decoding. Corrupt saved bytes read as the unassigned defaults without rewriting storage.

The authored tests exercise native owned windows, key/mouse dispatch, field editors and marked text, a sheet, a tracking menu, a separate region selector, existing edit commands, draft preservation and complete control frames. These synthetic owned-window fixtures do not establish physical keyboard-layout behavior, real IME input-source behavior, OS/global hotkey delivery or physical-Mac acceptance. Native execution is pending MacCI; Linux source inspection is not native test evidence.
